## 阻塞项

### 1. 缺 `PrivacyInfo.xcprivacy`

2024 年起 App Store 上传会因缺失或不完整的隐私清单被拒（ITMS-91053 系列）。需要新建 `iosApp/iosApp/PrivacyInfo.xcprivacy` 并加入 target 的 Resources。

本 App 的实际情况使内容非常简单：

- `NSPrivacyTracking` = `false`（无追踪）
- `NSPrivacyTrackingDomains` = 空数组（无网络）
- `NSPrivacyCollectedDataTypes` = 空数组（不收集任何数据）
- `NSPrivacyAccessedAPITypes` = **需要逐项核实后填写**

最后一项不能靠猜。需要确认 Kotlin/Native + Skia + DataStore(okio) + Room/SQLite 这条链路实际调用了哪些 required-reason API，常见的候选是：

- `NSPrivacyAccessedAPICategoryFileTimestamp` — DataStore / Room 写文件时可能 stat 文件时间（若命中，理由码通常是 `C617.1`：仅访问本 App 容器内的文件）
- `NSPrivacyAccessedAPICategoryDiskSpace` — 若有可用空间检查（理由码 `E174.1`）
- `NSPrivacyAccessedAPICategoryUserDefaults` — 若任何依赖用了 `NSUserDefaults`（理由码 `CA92.1`）

**核实方法：** 对 `Shared.framework` 与 app 二进制跑符号扫描（例如 `nm -u` 找 `NSFileManager` 时间戳相关、`NSUserDefaults`、`statfs`），或直接上传一次 TestFlight 构建让 Apple 的自动检查列出缺失项——后者最省事，且不会公开发布。

### 2. iPad 设备族与竖屏锁冲突

现在同时声明了 iPad 支持（`UIDeviceFamily` 含 `2`）和仅竖屏。后果有两个：

- App Store Connect 会**要求上传 13 英寸 iPad 截图**（2064×2752 或 2048×2732）
- iPad 上竖屏锁的体验会被审核质疑，且 iPadOS 新窗口系统下表现不佳

两条路选一条：

- **路线 A（省事，推荐首发）：** `UIDeviceFamily` 改为仅 `1`（iPhone）。iPad 用户仍可以兼容模式安装，无需 iPad 截图，无需处理横屏。
- **路线 B（体验好，工作量大）：** 保留 iPad，放开横屏。共享代码里 ADR-0026 的 ≥840dp 双栏本来就存在，iPad 横屏会直接点亮它——但需要真机验证双栏、键盘、PHPicker 在横屏下的表现，并补 iPad 截图。

首发建议走 A，把 B 留给 3.1。

### 3. 中文缺 Add 权限文案

`NSPhotoLibraryAddUsageDescription`（存图到相册时弹）只有英文。中文用户会看到英文提示。两个 `InfoPlist.strings` 各补一行：

- zh-Hans：`"NSPhotoLibraryAddUsageDescription" = "把加好水印的照片保存到你的相册。";`
- zh-Hant：`"NSPhotoLibraryAddUsageDescription" = "把加好浮水印的照片儲存到你的相簿。";`

### 4. 无归档 / TestFlight 通道

现在 CI 只做 Simulator 测试和 `CODE_SIGNING_ALLOWED=NO` 的构建，从没产出过可上传的 `.ipa`。首次提交可以先手工在 Xcode 里 Archive → Distribute，之后再考虑加 workflow。手工路径需要：Distribution 证书 + App Store provisioning profile（Automatic 签名会自动申请）。

## 建议补的配置

### `ITSAppUsesNonExemptEncryption`

本 App 无网络、不使用非豁免加密。在 `Info.plist` 加：

```xml
<key>ITSAppUsesNonExemptEncryption</key>
<false/>
```

这样每次上传就不用再回答出口合规问题。

### 隐私政策 URL（App Store Connect 必填）

复用现有的：

- 英文：`https://github.com/rosuH/EasyWatermark/blob/master/PrivacyPolicy.md`
- 中文：`https://github.com/rosuH/EasyWatermark/blob/master/PrivacyPolicy_zh-CN.md`

**注意：** 这两份策略是 Android 时代写的。上架前通读一遍，确认它涵盖了 iOS 的相册读取（ADR-0029 的 Library Read）与相册写入，措辞上不要只提 Android。

### 审核风险预案

- **可选权限被误判为强制：** 审核可能不理解 Library Read 是可选的。在审核备注里明确「拒绝相册读取后，选图、编辑、导出全部照常工作」，并说明弹窗出现的时机（选图时）。
- **UI 设计归属：** UI 由 @tovi 设计（`https://tovi.fun/`）。若审核问素材授权，需要能说明。
- **付费墙缺失：** 如果 iOS 首发免费而 Android 付费，无需解释；但两边描述文案不要互相矛盾。
