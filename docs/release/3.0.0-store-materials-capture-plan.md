# 3.0.0 全平台物料拍摄清单

**状态：** 待执行 · **日期：** 2026-08-16 · **适用：** Google Play / F-Droid / GitHub Releases / App Store / 桌面端

这份文档回答两个问题：**要拍什么**、**怎么拍才符合各商店规格**。按「先定场景，再按平台批量出图」的顺序组织，避免同一个界面反复摆拍。

## 先决事实

- **现有 Android 截图全部作废。** `fastlane/metadata/android/{en-US,zh-CN}/images/phoneScreenshots/1-4.jpg` 拍的是 View 版 UI，3.0.0 是完全重写的 Compose 界面，一张都不能复用。
- **App 是强制深色。** 产品主题固定 dark（ADR-0011），不需要浅色/深色两套。
- **编辑器主题会跟随照片取色**（ADR-0027）。这意味着**选什么样张直接决定截图配色**——这是卖点，建议刻意用一张色彩鲜明的照片。
- **仓库里没有 feature graphic**（Play 必需的 1024×500）。要么 Play Console 里已有旧的，要么这次得新做。
- 现有 14 个语言的 fastlane 目录中，只有 `en-US` 和 `zh-CN` 有图。其余语言复用英文图即可。

### 样张准备（拍之前先备好）

准备 3–4 张**你有权公开使用**的照片，避免肖像权/版权问题：

- 一张**色彩鲜明**的风景或静物 → 用于 S2/S3，让内容取色主题好看
- 一张**模拟证件/文档**的图 → 呼应「防止身份证照片被滥用」的核心场景（自己做一张假的，别用真证件）
- 两张任意图 → 用于 S7 胶片条凑多图

水印文案建议用有说服力的真实句子，例如 `仅供 XX 办理 XX 使用` / `For XX verification only`，比默认的 emoji 更能传达用途。中英文各准备一版。

## 二、Google Play

### 规格

| 素材 | 规格 | 数量 | 必需 |
|---|---|---|---|
| 手机截图 | 边长 320–3840px，**最长边 ≤ 2× 最短边** | 2–8 | 是（最少 2） |
| 手机截图（想进推荐位） | ≥1080px，9:16 竖屏（即 ≥1080×1920） | ≥4 | 推荐 |
| 平板截图（7"/10" 各一组） | 边长 1080–7680px，16:9 或 9:16 | 各 ≤8，≥4 才有平板推荐位 | 支持平板则强烈建议 |
| Feature graphic | **正好 1024×500**，JPEG 或 24 位 PNG，无 alpha | 1 | **是** |
| 应用图标 | 512×512，32 位 PNG 带 alpha | 1 | 是 |
| 宣传视频 | YouTube 链接 | 0–1 | 否 |

### ⚠️ 设备分辨率陷阱

你手上的 OnePlus 8T（KB2000）是 **1080×2400**，比例 1:2.22，**超过 Play 的 2:1 上限，原图传不上去**。

两个解法，推荐第一个：

**方案 A — 建一个 1080×1920 的模拟器（推荐）**
原生 9:16，既满足上限也满足推荐位门槛，不用裁剪。

**方案 B — 临时改真机分辨率**

```bash
adb -s 4ddb1c5b shell wm size 1080x1920
adb -s 4ddb1c5b shell wm density 420
# ... 拍完 ...
adb -s 4ddb1c5b shell wm size reset
adb -s 4ddb1c5b shell wm density reset
```

拍完**务必 reset**，否则手机会一直卡在这个分辨率。

### 拍摄命令

```bash
# 装 3.0.0 debug 包（与线上 2.10.0 可共存，applicationId 带 .debug 后缀）
./gradlew :app:assembleDebug
adb -s 4ddb1c5b install -r app/build/outputs/apk/debug/app-debug.apk

# 单张截图
adb -s 4ddb1c5b exec-out screencap -p > s2-editor-text.png

# 录屏（宣传视频用）
adb -s 4ddb1c5b shell screenrecord --size 1080x1920 /sdcard/demo.mp4
adb -s 4ddb1c5b pull /sdcard/demo.mp4
```

**注意：** 若用 debug 包拍摄，应用名会显示 `Easy WaterMark-Debug`。要出正式物料，请用 release 包（或临时改 debug 的 `applicationIdSuffix`/名称），别把 `-Debug` 字样发到商店。

### 拍摄命令

本机已有正好对上尺寸的模拟器：

| 模拟器 | 原生分辨率 | 对应要求 |
|---|---|---|
| iPhone 17 Pro Max | 1320×2868 | 6.9" 基准尺寸 ✅ |
| iPad Pro 13-inch (M5) | 2064×2752 | 13" 基准尺寸 ✅ |

```bash
# 启动（iPhone 17 已在运行中，不要关它）
xcrun simctl boot "iPhone 17 Pro Max"

# 截图 — 直接就是 1320×2868，无需缩放
xcrun simctl io "iPhone 17 Pro Max" screenshot s2-editor-text.png

# 录屏
xcrun simctl io "iPhone 17 Pro Max" recordVideo --codec h264 preview.mov
# 结束按 Ctrl+C；App 预览需转成 886×1920 再上传
```

**模拟器的坑：** 模拟器相册默认只有 Apple 的示例图。先把样张拖进模拟器窗口导入相册，再走选图流程。另外 Library Read 权限弹窗在模拟器上行为正常，可以顺便拍一张「拒绝权限也能用」的证据图留档（不必上传商店）。

## 四、桌面端（GitHub Releases / README）

没有强制规格，但首次发布桌面版需要说服力。

| 素材 | 建议 | 用途 |
|---|---|---|
| 窗口截图（双栏 ≥840dp） | 2560×1600 左右，带窗口阴影 | README 头图 |
| 拖入图片演示 | GIF 或 mp4，10–15 秒 | README |
| 三平台合影 | macOS / Windows / Linux 各一张窗口图 | Release note |

macOS 拍窗口（带阴影）：`Cmd+Shift+4` 然后按 `Space` 点窗口。

启动桌面版并直接带图进编辑器，省去走文件对话框：

```bash
./gradlew :desktopApp:run -PewmAutoOpen=/绝对路径/样张.jpg -PewmW=1440 -PewmH=900
```

⚠️ **发布说明里必须写清**：当前是**未签名**包，macOS 只有 Apple Silicon（arm64），Windows 会有 SmartScreen 提示，macOS 会有 Gatekeeper 提示。

`fastlane/metadata/android/en-US/full_description.txt` 里有几处已经过时：

- 移除：图片预压缩恢复提示、应用内更新日志页
- 新增平台：macOS / Windows / Linux 桌面版（未签名测试版）、iOS 版

## 六、执行顺序（建议一次搞定）

1. **准备阶段**：选好 3–4 张样张，定好中英文水印文案，决定 iPad 路线
2. **Android**：建 1080×1920 模拟器 → 装 release 包 → 按 S1–S10 拍英文 → 切中文重拍 → 存进 fastlane 目录
3. **iOS**：iPhone 17 Pro Max 模拟器 → 导入样张 → 按 S1–S10 拍英文 → 切中文重拍（→ 若走路线 B，iPad Pro 13" 再来一轮 + L1）
4. **桌面端**：`-PewmAutoOpen` 起窗口 → 拍 L1/L2 + 三平台合影
5. **平面素材**：做 1024×500 feature graphic
6. **文案**：改 `full_description.txt`（en-US + zh-CN），写 3.0.0 release note
7. **可选**：剪 15–30 秒预览视频（Android 录屏 + iOS simctl 录屏）
