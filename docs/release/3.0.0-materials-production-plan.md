# 3.0.0 物料生产方案

**状态：** 方案，待确认后执行 · **日期：** 2026-08-16
**配套：** [拍摄清单](3.0.0-store-materials-capture-plan.md)（场景与商店规格）· [iOS 上架准备](3.0.0-ios-app-store-readiness.md)

拍摄清单回答「拍什么、多大」。这份回答「**怎么做得好看、怎么自动化、谁做哪一步**」。

核心思路：**原始截图全部自动化产出，视觉包装用可版本化的模板渲染，只有创意决策需要人。** 因为 2 语言 × 10 场景 × 4 设备类 ≈ 80 张图，手工摆拍不可能保持一致，改一版文案也不能全部重拍。

## 零、开工前的两个硬阻塞

### 1. Fill/Stroke 落地前不能开拍

另一个会话正在把填充/描边控件加回编辑器。它会**改变 Style 选项行的内容**，所有涉及样式区的截图（S2/S3/S4）现在拍完就作废。

**必须等它合并后再开始捕获。** 这期间可以做的：选图、写文案、搭模板、准备设计系统。

### 2. iPad 横屏（路线 B）要先改代码

`Info.plist` 现在还是 `UISupportedInterfaceOrientations` 只有 `Portrait`。路线 B 需要放开 `LandscapeLeft` / `LandscapeRight`（iPad 可用 `~ipad` 变体单独放开，iPhone 保持竖屏）。

**顺带一个发现：** 双栏阈值是 840dp，而各 iPad 竖屏逻辑宽度是——

| 机型 | 竖屏宽度 | 当前布局 |
|---|---|---|
| iPad Pro 13" / Air 13" | 1032 / 1024 pt | **双栏** |
| iPad Pro 11" | **834 pt** | 堆叠（差 6pt） |
| iPad Air 11" / iPad | 820 pt | 堆叠 |
| iPad mini | 744 pt | 堆叠 |

好消息：**商店必需的 13" 竖屏截图自带双栏**，不用横屏也能展示大屏形态。
待确认：11" 竖屏差 6dp 掉回手机布局，是有意为之还是应该把阈值调到 ~820？这是产品决定，不是物料问题，但会影响 11" iPad 用户的第一印象。

## 一、样张策略

样张直接决定成片质感，而且这个 App 的截图里照片占了 80% 面积。

### Unsplash 可用，但有明确红线

Unsplash License 允许商用、不强制署名，**但只授予版权，不覆盖**：

- **可辨识的人脸** — Unsplash 不核实肖像授权，商用风险自负
- **商标 / logo / 品牌**（包括衣服鞋子上的）
- 画作等被拍摄的受版权保护作品

对我们来说结论很简单：**只用风景、建筑、静物、纹理、俯拍平铺**，一张人脸都不要。这刚好也是水印展示效果最好的类型。

### 选图标准（水印场景特有）

- **中间调为主**：纯白或纯黑区域会让水印要么刺眼要么看不见
- **不要太碎**：高频细节（树叶、人群）会把水印文字吃掉
- **构图留白**：中央区域相对干净，水印平铺才好看
- **色彩有记忆点**：内容取色主题（ADR-0027）会从照片提取强调色，鲜明的照片能让整个界面配色出彩

### 建议 4 张

| 编号 | 类型 | 用途 | 来源 |
|---|---|---|---|
| P1 | 色彩鲜明的风景/建筑 | S2/S3 主图，展示取色主题 | Unsplash |
| P2 | 静物 / 平铺俯拍 | S4/S6，中间调好放水印 | Unsplash |
| P3 | **伪造的证件/文件** | 呼应核心使用场景 | **自制**，绝不用真证件 |
| P4 | 任意风景 | S7 胶片条凑数 | Unsplash |

P3 是产品叙事的关键一张——「防止身份证照片被滥用」是这个 App 存在的理由。必须自己用 Figma 画一张明显虚构的证件（假姓名、假号码、加 SPECIMEN 字样），不要用任何真实证件或网图。

### License 留档

即使 Unsplash 不要求署名，也建议在仓库留一份可审计记录：

```
docs/release/assets/photos/
  P1-<slug>.jpg
  P2-<slug>.jpg
  P4-<slug>.jpg
  CREDITS.md   ← 每张：Unsplash 链接、作者、作者主页、下载日期、License 版本
```

这不是法律义务，是出事时的举证材料。同时也是对摄影师的基本尊重。

**不要把样张 commit 进主仓库**（体积 + 无关）；建议放 release 资产或单独分支，`CREDITS.md` 本身可以进仓库。

## 二、捕获管线（我可以自动化的部分）

目标：一条命令产出全部原始截图，改文案/换样张后可一键重跑。

### Android — 完全可自动化

`adb` 什么都能做，这是最省事的一端。

```bash
# 分辨率：用 1080x1920 AVD，或临时改真机（拍完必 reset）
adb shell wm size 1080x1920 && adb shell wm density 420

# 切语言（Android 13+ 按应用切，不动系统设置）
adb shell cmd locale set-app-locales me.rosuh.easywatermark --locales zh-CN

# 灌样张
adb push P1.jpg /sdcard/Pictures/

# 驱动 + 截图
adb shell input tap X Y
adb exec-out screencap -p > out/zh/S2.png
```

我会把整套写成 `scripts/capture-android-store.sh`，按场景表逐张产出。

### iOS — 用 XCUITest 驱动，最稳

PHPicker 的网格单元格在当前工具链下不可寻址（已知限制 E14），但**坐标点击可以**。方案是加一个仅用于物料的 XCUITest 目标：

1. `xcrun simctl addmedia <udid> P1.jpg P2.jpg P3.png P4.jpg` 灌相册
2. XCUITest 启动 App，按场景表导航（PHPicker 用归一化坐标点击）
3. 每个场景 `XCTAttachment` 存全分辨率截图
4. 从 `.xcresult` 里用 `xcresulttool` 批量导出

语言通过启动参数切：`-AppleLanguages (zh-Hans) -AppleLocale zh_Hans_CN`。

设备直接用原生就对尺寸的模拟器，不需要任何缩放：

| 模拟器 | 原生 | 对应商店档位 |
|---|---|---|
| iPhone 17 Pro Max | 1320×2868 | 6.9"（必需） |
| iPad Pro 13-inch (M5) | 2064×2752 | 13"（路线 B 必需） |

**这是本方案里唯一需要新写代码的部分**（一个 DEBUG-only 的测试目标，不进产品包）。如果你想省掉它，退路是我用 Computer Use 直接操作模拟器窗口——能做，但每次都要重来一遍，改文案时无法批量重跑。

### 桌面端 — 半自动

```bash
./gradlew :desktopApp:run -PewmAutoOpen=/abs/P1.jpg -PewmW=1440 -PewmH=900
```

起窗口后用 `screencapture -l <windowid>` 抓带阴影的窗口图。Windows / Linux 那两张需要你在对应机器上手动抓，或者接受只给 macOS 图。

## 三、视觉包装（让它「好看」的那一步）

原始截图 ≠ 商店物料。现代 App Store 首屏基本都是「设备框 + 一句话标题 + 品牌背景」。

### 推荐做法：HTML/CSS 模板 + 无头 Chrome 渲染

不用 Figma 手工排 80 张。做一个模板，把截图和文案作为变量注入，用无头 Chrome 按精确像素输出：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --hide-scrollbars \
  --screenshot=out/appstore-en-01.png \
  --window-size=1320,2868 \
  --force-device-scale-factor=1 \
  "file:///.../frame.html?shot=S2&lang=en&size=69"
```

好处很实在：

- **像素精确**，不会出现 App Store Connect 的尺寸报错
- **可版本化**，模板进 git，改一次全部重渲染
- **多语言零成本**，同一模板换 `lang` 参数
- **多尺寸零成本**，6.9" / 13" / Play 1080×1920 共用一套设计

Figma 仍然有用——用来**设计**这套视觉（定色、定字号、定间距），定稿后翻译成 CSS。不要用它当生产线。

### 视觉系统建议

和 App 本身的调性保持一致：强制深色 + 内容取色。

| 元素 | 建议 |
|---|---|
| 背景 | 近黑（#0B0B0D 左右）+ 从样张提取的强调色做低透明度径向渐变 |
| 标题 | 2 行内，字重 600–700，紧字距；中文用系统字重而非伪粗体 |
| 设备框 | 无边框圆角截图 + 细微高光边，比真实设备框更现代；或用真机框保守一点 |
| 构图 | 标题占上 1/4，设备占下 3/4 且底部出血（暗示可滑动） |
| 一致性 | 8pt 网格，所有图共用同一套 token |

### 文案（每张一句，这是转化关键）

按场景表的优先级，前 3 张要讲完整个价值主张：

| 位次 | 场景 | 英文方向 | 中文方向 |
|---|---|---|---|
| 1 | S2 文字水印铺满 | 说清「铺满整张，难以抹除」 | 同上 |
| 2 | S3 颜色面板 | 说清「颜色透明度随你调」 | 同上 |
| 3 | S4 布局选项 | 说清「间距角度平铺自由」 | 同上 |
| 4 | S7 多图胶片条 | 说清「一次处理一整批」 | 同上 |
| 5 | S9 导出面板 | 说清「导出即抹除 EXIF」 | 同上 |
| 6 | S10 / 品牌 | 说清「全程离线，无网络权限」 | 同上 |

**我建议最后一张专门讲隐私**——这是这个 App 相对所有竞品的唯一护城河，而且「没有网络权限」是可验证的硬事实，不是营销话术。

具体文案等视觉定稿后一起给你几组备选，不在这份方案里定死。

## 四、视频

### 工具分工

本机装了 **Screen Studio 3.7.4**（成熟的产品演示录制工具，自动变焦、平滑光标、背景与设备框）和 **ScreenSage Pro 0.3.13**。

建议 **Screen Studio 作主力**：它的自动变焦和光标平滑是这类产品视频质感的主要来源，而且直接支持导出竖屏比例。

### 内容结构（30 秒，一条母带剪多个版本）

| 时间 | 内容 |
|---|---|
| 0–3s | 一张敏感照片（P3 伪造证件）静止，制造问题感 |
| 3–8s | 选图 → 进编辑器，水印瞬间铺满 |
| 8–16s | 调颜色、透明度、角度——展示可控性 |
| 16–22s | 切多图，批量导出 |
| 22–27s | 大屏形态（桌面端或 iPad 双栏）一闪 |
| 27–30s | 收在「完全离线」的品牌页 |

### 各平台交付

| 平台 | 规格 | 说明 |
|---|---|---|
| App Store 预览 | 6.9" 用 886×1920，15–30 秒 | 从母带剪 |
| Play 宣传视频 | YouTube 链接 | 可用完整 30 秒 |
| README / Release | GIF 或 mp4 | 桌面端拖入演示单独一条 |

母带素材来自模拟器/真机录屏（`simctl io recordVideo` / `adb screenrecord`），Screen Studio 负责包装。**不要直接把模拟器录屏当成片**——没有变焦和节奏，观感很业余。

### 双栏阈值已从 840dp 降到 800dp

已实施（ADR-0026 amended 2026-08-16）：`EDITOR_LAYOUT_EXPANDED_MIN_WIDTH_DP` 840 → 800。

选 800 而不是 820 的理由：820 正好等于 iPad Air 11" 的竖屏宽度，零余量，任何 safe-area 内缩都会掉回堆叠；而 iPad 阵容里 744（mini）和 820 之间没有机型，所以 800 和 820 对 iPad 效果完全相同，800 只是更抗误差。inspector 是固定 360dp 栏，800dp 时预览区仍有 ~416dp，比 Compact 路径已经在服务的任何手机都宽。

顺带修掉了三处绕过共享判断的裸 `>= 840`（Android About / Android 导出 / iOS About），改走 `usesLargeScreenDialog`。否则 iPad Air 11" 竖屏会出现「编辑器双栏、导出却还是手机底部抽屉」的割裂。

对物料的影响：**所有 iPad（除 mini）竖屏都出双栏**，13" 和 11" 截图都能展示大屏形态。
