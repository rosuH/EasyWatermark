# ADR-0041: Reusable sticker asset library

Status: Proposed (design direction approved by owner on 2026-11-14; implementation pending verification and device sign-off).

## Context

The interim Sticker Library stored 10 fields per saved sticker (`id`, `icon`, `textSize`, `alpha`, `degree`, `tileMode`, `hGap`, `vGap`, `offsetX`, `offsetY`) inside `stickers.catalog`, while applying a saved user sticker overwrote 6 live config fields plus `CLAMP` offset — whereas applying a built-in Phosphor sticker kept live styling, reset `CLAMP` offset to center, and wrote a new UUID PNG on every click. This created a mismatch between built-in and user stickers, prevented `BuiltInSticker` cells from showing active selection, left the `StickerPanelSheet` open after importing a new icon, and left `Repeat` mode without an obvious one-tap clear action alongside `Single` mode's on-canvas `×` handle.

Meanwhile, saving multi-field layout/style snapshots belongs to a dedicated global Presets system rather than per-image sticker assets.

## Decision

- **Asset-only `Sticker` model:** `Sticker` stores `(id: String, icon: MediaRef)` only. `StickerCatalog` writes 2 fields per line (`id` and `icon.value`) and continues decoding legacy 10-field catalog lines by taking `parts[0..1]` while rejecting malformed lines.
- **Swap icon only, preserve live layout and placement:** Selecting either a built-in mark or a saved user sticker dispatches only `WatermarkConfigChange.Icon(ref)`. Live `WaterMark` style/layout (`textSize`, `alpha`, `degree`, `tileMode`, `hGap`, `vGap`) and valid `Single` (`CLAMP`) fractional offsets in `0f..1f` remain untouched; `StickerPlacement.sanitizeLiveSingleOffset` coerces only non-finite or out-of-bounds `Single` offsets. Remove unused `saveCurrentSticker()` / `onSaveSticker` host wiring.
- **Deterministic built-in icon files:** The 12 `BuiltInSticker` entries use stable keys, in display order `verified`, `original`, `no_ai`, `no_repost`, `do_not_copy`, `rights_reserved`, `sample`, `private`, `smiley`, `seal_original`, `no_reprint`, `anti_theft`, written atomically to deterministic app-owned filenames (`icon-builtin-<key>.png` on Android/Desktop; `icon_builtin_<key>.png` on iOS). Repeated built-in picks overwrite in place without leaking UUID PNGs, and `BuiltInSticker.matches` accepts both filename forms so cell selection highlight works across platforms. The art is this repository's own pack (`docs/design/sticker-pack/`, lettering outlined from OFL fonts) shipped as lossless transparent WebP at 512 px on the long edge, replacing the 6 monochrome Phosphor vectors. `Painter.toStickerBitmap(maxEdgePx = WatermarkIconCache.ICON_MAX_EDGE_PX)` preserves the painter's intrinsic aspect ratio at a 256 px long edge and applies no tint, so full-colour marks render as drawn. The prototype key `copyright` ships as `rights_reserved` on purpose: iOS keys one file per sticker, so a new key writes a new file instead of reusing the stale white `icon_builtin_copyright.png` still sitting on test devices.
- **Direct inline presentation & unified architectural geometry:** All three hosts (Android, Desktop, iOS) route `useLargeDialog` through `usesLargeScreenDialog(layoutClass)` (`>= 800 dp` per ADR-0026) and align sticker UI to `EwmTheme.shapes.chipRadiusDp` (`2.dp` corners), `editorAccentColor()`, `editorSelectedContainerColor()`, and `editorChromeColor()`. Idle tiles carry no fill and no border; only the applied tile gets `editorSelectedContainerColor()` plus a `1.5.dp` accent border, with no corner badge:
  - **Compact/Medium (`< 800 dp`):** `StickerPanelOnIcon` renders a direct horizontal `InlineStickerRail` (`testTag("stickerInlineRail")`) inside the fixed `96.dp` bottom control slot for 1-tap unobstructed live preview: `[None] [Import] [stickers …]` scroll horizontally with `[All]` (`stickerExpand`) pinned at the trailing end under a chrome-coloured fade. `None` (`stickerClear`) is always present and first, and is one option of the same single-choice group as the stickers — selected exactly when no icon is applied, and calling `onClear` on tap, so `Repeat` and `Single` share one clear affordance. `Import` is a wide labelled tile while no user sticker exists and icon-only afterwards. Tile order (applied built-in first, then user stickers newest-first, then enum order) is recomputed when the rail enters composition, when the panel closes, and when the user list changes — never under the finger.
  - **Docked panel:** `All` opens the `2.dp` darkroom `StickerPanelSheet` docked in the bottom overlay slot, non-modal and with no scrim (`dismissOnSelect = false` for continuous live comparison): a `FontPanel`-shaped header of title plus one close button and no Remove action, then one vertically scrolling 4-column body (`Mine` label row hosting `Manage`, then `Built-in`, which is shown even with no user stickers). The slot gives the panel a fixed `max(bottomChromeHeight, min(0.48 × rootHeight, 440.dp))` height and the preview frame refits so its bottom edge meets the panel. Dismissal is the close button, a `>= 48.dp` drag on the handle, or system Back.
  - **Expanded/Wide (`>= 800 dp`):** `StickerPanelOnIcon` embeds the same 4-column body inline in `EditorInspectorPanel` (`stickerInlinePanel`) with no title row and no Remove action, plus hover `×` single delete (`stickerDelete_<id>`) for desktop pointers.
  - **Selection mode (manage):** entered by the `Manage` text button or a long press on a user sticker in the rail, panel or inspector. The label row is replaced in place by `n selected` (`stickerSelectedCount`), select all / deselect all, and `Done` (`stickerManageDone`); user stickers carry an `18.dp` checkbox; `None`, `Import` and every built-in drop to alpha `0.3`, ignore input without moving, and render in their idle look — the applied highlight is not drawn in this mode, though `selected` semantics still report what is applied; a footer holds one full-width `48.dp` error-outlined `Delete (n)` that asks once with `EwmConfirmDialog` before calling `onDeleteUsers`. Selection mode ends on `Done`, on panel close, or when the user sticker list empties. Accent colour marks selection; only the delete control uses the error colour.
  - **Canvas:** the drag-to-remove target is a `40.dp` `chipRadiusDp` chip rather than a `48.dp` circle pill.
  - **Rotated Single-mode selection box:** `RasteredWatermarkCell` and `OverlayCell` propagate unrotated content dimensions (`contentWidth × contentHeight`), and `InteractiveOverlayPreview` rotates the crisp `1.dp` hairline selection box + free-corner architectural L-brackets in 1:1 lockstep with the watermark (`computeRotatedSelectionFrame`) alongside unified `24.dp` `2.dp`-radius corner handles and a monospace degree HUD.

## Acceptance

- Common unit/UI tests verify `StickerCatalog` round-trip and legacy 10-field decode, `StickerPlacement.sanitizeLiveSingleOffset`, `RasteredWatermarkCell` unrotated content bounds across angles, `computeRotatedSelectionFrame`, and rotated handle coordinate tracking (`:shared:desktopTest`, `:shared:iosSimulatorArm64Test`).
- `StickerPanelSheetUiTest` covers the presentation contract on the same two targets: the 12-entry built-in order with both icon filename forms, `toStickerBitmap` aspect ratio / 256 px long edge / no tint, rail layout (None first and always present, wide Import only without user stickers, `All` pinned last, no reorder on tap), docked panel (header close only, apply keeps it open, the empty-library Import tile spanning the rest of its row — 3 of 4 columns, one cell high — `Built-in` label without user stickers), selection mode (None / Import / built-ins inert, one confirm before `onDeleteUsers`, exit on `Done` / close / empty list), the inline inspector, and the C1 overlay height plus preview refit in a normal and a 360 dp-high window. `PreviewGestureUiTest` pins the `40.dp` drag-to-remove chip.
- `PickerFlowUITests` (`testStickerSheetOpensFromIcon`, `testSeededStickerApplyThenDelete`) proves the rail tags, the trailing `All` tile and the always-present `None` tile on a real iOS simulator.
- Android unit and debug APK builds pass (`:app:testDebugUnitTest`, `:app:assembleDebug`), and `:desktopApp:classes` compiles cleanly.
- Physical-device / visual review via `e2e-testmap` Mode B remains required before merge.
