# EasyWatermark Domain Context

Domain vocabulary and invariants. Agents and humans: use these words with these meanings; update this file when a concept is added, renamed, or retired (docs-with-code gate).

## Core concepts

| Term | Meaning |
|---|---|
| **Watermark cell** | The small offscreen bitmap containing one rendered instance of the watermark (text or icon, already rotated, with gap padding baked in). Built once, then tiled or placed; backing rasters cap at `WatermarkCellComposer.MAX_CELL_RASTER_EDGE_PX` (`2048`) while preserving logical tile geometry (`RasteredWatermarkCell`), preventing Android `RecordingCanvas` >100 MiB crashes. **ADR-0018:** product composition boundary is `CommonWatermarkPipeline` (decoded background + `WaterMark` + `TextRasterEnv` + optional icon + optional prepared `FontFamily` + fractional offsets → composed `ImageBitmap`). Android: `AndroidCommonRaster`. Desktop: `composeRealImage` + `DesktopRenderRequest`. iOS: Preview `IosPreviewRaster` (in-memory, display-fit buckets) and Final Export `IosFinalRenderSpine` + `IosRenderRequest` (full-res, format/quality/offset). Android native `WatermarkRenderer` remains measurement/golden oracle only. |
| **Tile mode** | How the cell covers the photo. `REPEAT` (UI: "repeat") = shader-tiled across the whole image. `CLAMP` (UI: "decal") = single instance at a draggable fractional offset. The model uses commonMain `WatermarkTileMode`; DataStore stores explicit `storageId` values that mirror the historical Android `Shader.TileMode.ordinal` values for byte-identical preferences. Android render/export converts only at the edge (`WatermarkTileMode.toShaderTileMode()` / `WaterMark.obtainTileMode()` in `TileModeExt.kt`). `MIRROR`/`DECAL` are representable but unreachable from UI. |
| **Viewing transform** | UI-local preview zoom/pan, reset on photo change or Reset view. Does not change watermark config or exported pixels (ADR-0040). |
| **Repeat origin** | Global `repeatOffsetX/Y`, normalized to photo dimensions and defaulting to zero. Moves the entire repeating pattern; CLAMP keeps its per-photo Session offsets (ADR-0040). |
| **Gap (hGap/vGap)** | Spacing between tiles, percent-of-cell: `finalSize = cellSize * (gap/100 + 1)`. |
| **Rotation-AABB** | The axis-aligned bounding box of rotated content: `w' = w·cos+h·sin`, `h' = w·sin+h·cos`, with the degree piecewise-normalized (0–90 → d; 90–270 → \|180−d\|; else 360−d). Cell dimensions derive from it (text mode). Icon mode uses the icon **diagonal** for both dims instead. |
| **textSize dual duty** | For text: image-space font sizing via `WatermarkGeometry.fontPx` relative to `REF_WIDTH = 1000` (independent of window/view size). For icon: scale ratio = `textSize / 14f`. |
| **Image-space sizing** | Text-mode watermark sizing defined relative to the source image width (`WatermarkGeometry.REF_WIDTH = 1000`), independent of window/view size, so text preview and export scale consistently across Android, Desktop, and iOS. Image-mode cells instead size from the icon bitmap dimensions scaled by `textSize / 14f`. |
| **Fractional offset (offsetX/offsetY)** | CLAMP-mode watermark position as 0..1 fractions of the displayed photo bounds. Survives across preview/export because it is resolution-independent. |
| **inSample preview decode** | Android preview decode uses official `BitmapFactory.inSampleSize` (power of two, starts at **1**): subsample while either half-dimension still meets or exceeds the pane (`FIT_CENTER` / `ContentScale.Fit` semantics, preventing extreme-aspect-ratio panoramas and tall screenshots from exceeding `RecordingCanvas` or preview working-set bounds). Export decodes full-res. iOS/Desktop do not use this helper — they decode to a `PreviewResolutionPolicy` long-edge bucket and keep native pixels when the source is already ≤ that bucket. |
| **Low-resolution source hint** | Non-blocking caption on the editor preview when source long edge is below 720 (`PreviewResolutionPolicy.isLowResolutionSource`). Unknown/default 1×1 dims do not trigger. Export stays native pixels; no upscale. |
| **ViewInfo (retired concept)** | Historical snapshot of the legacy `WaterMarkImageView` size/matrix once used to derive export scale. Removed with `WaterMarkImageView` — export scale is image-space and Compose preview needs no view snapshot. Do not reintroduce. |
| **Golden two-tier** | (1) Strict same-platform goldens: local pinned-env FNV gate (`WATERMARK_GOLDEN_STRICT=true`, never PR CI). (2) Cross-platform structural/perceptual gates with per-platform baselines — JVM/iOS Skia text ≠ Android Minikin text even with a bundled font (ADR-0010). |
| **Parity baseline** | Production release **v2.10.0** (ADR-0011) is the visual/behavioral reference baseline; intentional product changes are recorded in ADRs. |
| **Shared CMP UI route** | Product screens live in `:shared` `commonMain/ui/`. Platform-native UI is limited to app/window entry, system pickers, share/save/permission surfaces, platform capability glue, and renderer surfaces. |
| **Product shell About overlay** | `ProductShellHost` keeps Launch or Editor composed under About (`ProductShellNav.overlayBase`). About enter/exit is a sibling overlay (Activity-stack semantics). Do not swap About through the Launch↔Editor `AnimatedContent` — that remounts Launch mid-pop and hitches the 180 dp logo mesh. The under-tree `graphicsLayer` (scale 0.5 / x −15%) is **About-cover only** — a parent layer around Launch↔Editor forces both pages through one offscreen pass and hitches the short slide. `LocalShellObscured` is true for the whole About enter/exit **and** while the Launch↔Editor swap is running, so decorative mesh does not compete with the incoming Editor tree. |
| **I3 motion** | Product timed motion goes through `EwmMotionTokens` + `motionDurationMs` (`FastOutSlowInEasing`). Large-screen `EwmContentDialog` and **iOS/Desktop** process-first Launch reveal are fade+scale 0.97 @ `shellShortMs` (240 ms Full). Android first Launch frame is opaque (no process-first fade). Open Source is a shared overlay using the Launch↔Editor short H-slide+fade, not About 0.75/0.5. Filmstrip switch stays hard-cut (`previewCrossfadeDurationMs` = 0). No LaunchView springs (ADR-0023). |
| **ColdLaunchReveal** | Process-first Launch appear on **iOS and Desktop**. Play the fade **once** when the first `ProductShellHost` base route in this process is Launch. Not a `LaunchScreen` first-composition flag (Editor→Launch remounts Launch). Share-in Editor and later About must not replay. Android passes `playProcessFirstReveal = false` so the first frame is opaque Launch (2.x). No host hold, no `installSplashScreen`. **ADR-0032** (amended 2026-09-13). |
| **StartupTrace** | Gated cold-start probe (`EWM_STARTUP mark=<name> t_ms=<int>`). Off unless Android `debug.ewm.startup_trace=1` + `log.tag.EwmStartup`, Desktop `EWM_STARTUP_TRACE=1`, or iOS `-ewmStartupTrace`. Marks include `first_screen` (Launch laid out), `cold_reveal_done` (fade settled or skipped), `fully_drawn` (then Android `reportFullyDrawn()`). `onFirstScreen()` is once-only — `onGloballyPositioned` repeats. Not a Play/CI vital. Harness: `scripts/startup_bench.py`. |
| **Launch fill (`#262611`)** | Product first-pixel color: shared `DesignEditorBg`, iOS `LaunchBackground` / `ContentView.productBackground`, Android `splash_screen_background` (`windowBackground` + API 31+ `windowSplashScreenBackground`). **Not** Android XML `md_theme_dark_background` (`#1D1B16`). Android `MainActivity` uses `Theme.MyApp` (2.x). iOS launch screen is fill only (no icon). Empty/nested `UILaunchScreen` falls back to `systemBackground` and must not return. |
| **composeResources (product UI)** | **ADR-0019.** Product strings + chrome icons/logo live in `shared/src/commonMain/composeResources/` (`values(-*)/strings.xml`, `drawable/`). Shared screens use `stringResource(Res.string.*)` / `painterResource(Res.drawable.*)` / `SharedProductDrawables` / `FuncType.label()` / `FuncType.iconPainter()`. Packaging on AGP 9 + Android-KMP library requires `androidResources { enable = true }` on `:shared` and must not rewrite `org.jetbrains.compose.components.*` to AndroidX. **Weblate** still points at `app/src/main/res/values-*` until retarget (dual-write default EN until then). Not for watermark fonts or Room seed DBs. |
| **System-default watermark typeface** | Production Text-mode face resolution via Compose `FontFamily.Default` / platform resolver (ADR-0025). Not a bundled file. Bold/italic via platform synthesis. CJK coverage is an OS/language-pack property. Default remains the first font-panel row after ADR-0035. |
| **Custom watermark fonts** | User-selectable system faces and imported single-face TTF/OTF for text watermarks (**ADR-0035**). Identity is `WatermarkFontRef` (`Default` / platform `System` key / `Imported` SHA-256). Imports are hashed copies under app-private `watermark_fonts/`; system faces are not copied. Selection uses existing Session `WatermarkConfigChange.FontSelection` in **one** DataStore edit with style normalization. Preview and export resolve the same snapshot; failed resolve does not silently fall back to Default. Android API 23–28 lists generic families only. Local name search filters the list; outer panel height is window-based and does not follow query/result count. _Avoid_: packing watermark fonts in composeResources, online font APIs, OS-level font installation, a second live config, or a shared font ViewModel. |
| **Test-only bundled face** | Noto (or other) font files under test source sets (`desktopTest` / `androidTest`) for goldens and parity harnesses. Never a release payload (Play APK, iOS app, Desktop main resources). |
| **Supporting-pane editor** | Editor chrome pattern: **primary preview** + **secondary tools/inspector** (Material supporting-pane mapping for a media tool). Default dual-pane product shape on wide enough windows. **ADR-0026.** _Avoid_: calling the editor “list-detail”; list-detail is collection→item (e.g. optional gallery), not tool chrome. |
| **Three-zone batch editor** | **Withdrawn** for product chrome (ADR-0026 amended 2026-08-10). Was session library \| canvas \| inspector at ≥1440; left rail redundant with filmstrip. Do not reintroduce without ADR. |
| **Editor layout class** | Width-derived layout band for the shared editor (stack vs supporting-pane). Product breakpoints (ADR-0026, amended 2026-08-16): Compact **&lt;600**, Medium **600–799** (same vertical stack as Compact), dual-pane supporting-pane **≥800** (also for **≥1440** / `Wide` class). Filmstrip stays in the **primary preview pane** at every dual-pane band. |
| **WaterMark config model & rules** | Platform-neutral watermark configuration in `shared/commonMain/data/model/`: `WaterMark`, `WatermarkMode`, `TextTypeface`, `TextPaintStyle`, `WatermarkTileMode`, `FuncType`, `WatermarkConfigChange`, and pure normalization rules in `WatermarkConfigRules`. Storage keys and enum IDs remain byte-compatible with legacy Android preferences (`WatermarkMode.Text=0/Image=1`, `TextTypeface` 0–3, `TextPaintStyle` 0–1, `WatermarkTileMode.storageId`). Android render adapters (`obtainTileMode()`, `obtainSysStyle()`) stay in `:app`. |
| **MediaRef** | Platform-neutral image identity (`@JvmInline value class MediaRef(val value: String)` in `shared/commonMain`). Used in `WaterMark.iconUri` and `ImageInfo.uri` so DataStore round-trips without migration. Android `android.net.Uri` stays strictly at picker, gallery, decode, Coil, and save edges via `utils/ktx/MediaRefExt.kt`. |
| **ImageInfo** | Transient selected/export image state in `shared/commonMain/data/model/`, keyed by `MediaRef` with normalized `0f..1f` `offsetX`/`offsetY` fractional offsets. |
| **Domain config/template editors** | `WatermarkConfigEditor` and `TemplateEditor` in `shared/commonMain/domain/` hold platform-neutral write rules over `WaterMarkRepository` and `TemplateRepository`. Output format/quality edits write directly via `UserConfigRepository.updateFormat` / `updateCompressLevel`. Do not add speculative shared ViewModels, reducers, or IO `expect` layers without a named off-Android consumer or owner decision. |
| **DataStore & repositories** | `UserPreferences`, `UserConfigRepository`, and `WaterMarkRepository` live in `shared/commonMain` using `okio.IOException` and byte-compatible legacy DataStore keys (`SP_NAME`, `SP_KEY_*`). Keep at most one active `DataStore` instance per file in-process. Store creation uses plain per-platform functions (no `commonMain expect`/`actual`): Android keeps `PreferenceDataStoreFactory.create(produceFile, migrations)` with `SharedPreferencesMigration` and supplies localized default text + SDK-gated tile-mode mapping at the Koin edge; Desktop uses OS-native `DesktopAppPaths`; iOS uses `NSDocumentDirectory`. |
| **iOS platform edges** | `IosUserConfigBridge`, `IosWatermarkConfigBridge`, and `IosTemplateBridge` expose `suspend` value APIs to Swift without leaking `Flow`/`DataStore` into public Swift signatures. Imported icons persist under app-private `NSDocumentDirectory/watermark_icons/` via `IosIconPersistence`. Templates use Room KMP + `BundledSQLiteDriver`, seeded on first launch from bundled `ewm-db-ch.db` / `ewm-db-eng.db` via `IosTemplateSeed`. |
| **Desktop export folder & storage** | App data (DataStore prefs, Room templates seeded from `ewm-db-ch.db` / `ewm-db-eng.db`, imported icons via `DesktopIconPersistence`, fonts) lives under OS-native `DesktopAppPaths`. Export destination is a user-picked directory: macOS uses native AWT directory `FileDialog` (`apple.awt.fileDialogForDirectories` via `DesktopExportFolderChooser`, where cancel must not reuse the leftover directory); Windows/Linux use Swing `JFileChooser`. Open image / Save As stay file `FileDialog`. `:desktopApp` also supports `--headless` CLI rendering and `-PewmAutoOpen` window seam. _Avoid_: Swing `JFileChooser` on macOS. |
| **Wallpaper dynamic color** | Android-only whole-app Material You scheme seeded by the **system wallpaper** (OS extraction → M3 tokens). Consumed via `dynamicDark/LightColorScheme` / Material `DynamicColors`. **Does not exist** on iOS or Desktop (no public wallpaper/accent seed for third-party apps in this product). Policy: **ADR-0027** — drop OEM manufacturer allowlist; wall-follow is a user preference (not “force past OEM”). _Avoid_: calling iOS/Desktop theming “Material You”; conflating with **Content editor theme**. |
| **Content editor theme** | Full **Editor-session** Material 3 `ColorScheme` generated from the **currently selected photo** (filmstrip focus), not a thin background wash. Default **on**; while active it **outranks** wallpaper dynamic color on Android for the Editor surface (preview + inspector). Pure seed (no brand-amber harmonize in Editor). Always **dark** scheme (forced-dark parity). Leave Editor or toggle off → static brand (and Android wallpaper if enabled). Fail/no image → static brand fallback. **ADR-0027.** _Avoid_: “palette bg”, “dynamic color” alone. |
| **DynamicColorCapability** | Platform gate for **Wallpaper dynamic color only** (not content theme), in `shared/commonMain/.../platform`. Android delegates to `:cmonet`; Desktop/iOS report unavailable. Content editor theme must **not** be folded into this interface. `:cmonet` absorption remains owner-gated. |
| **Product UI image load (Coil)** | **ADR-0028.** UI chrome images (gallery, filmstrip, save-sheet thumbs, icon preview, content-theme **seed** thumbs) load via **Coil 3 on KMP** (`:shared` + platform Fetchers)—not ad-hoc `produceState`+`BitmapFactory`. Android product path keeps **MediaStore thumbnail** semantics (not bare content-URI full open). **Out:** watermarked editor preview composition, export full-res decode, renderer icon full decode for compose, golden fixture decodes. _Avoid:_ “Coil loads the watermark”; “`.data(Uri)` alone is fine for gallery”. |
| **ProductThumb** | Coil `data` for UI thumbs: `MediaRef` + maxEdgePx (+ purpose if needed). Platform Fetchers → MediaStore / file path / ImageIO. Shared max-edge with content-theme seed for memory-cache hits (**ADR-0028**). Request uses `Scale.FILL` to match filmstrip `ContentScale.Crop`. Android `loadThumbnail` fits the whole image into a square — extreme aspects that collapse the short edge are rejected and re-decoded so the short edge meets the cell (`ProductThumbFit`); fallback decode caps long edges at `ProductThumbFit.MAX_THUMB_LONG_EDGE_PX` (`4096`) and Android canvas safety clamps prevent `RecordingCanvas` >100 MiB crashes. |
| **Library Read** | iOS-only, **optional** Photos *read* authorization. Speeds **already-picked** editor photos via system derivatives. Not required to pick (PHPicker), save (add-only), export, or use any editor function. Declining = today’s ImageIO preview speed. _Avoid_: “no iOS Photos permission” (add-only save exists); “scan the library”; Android “storage / media permission”. |
| **Library derivative** | Unwatermarked PhotoKit pixels from `PHImageManager` for a picked `PHAsset`. **ADR-0033:** photo layer only — never on screen without a matching overlay cell for that bitmap’s width. Same-switch ImageIO `previewGen++` is not stale for that path; drop a late frame only if disposed, focus path changed, or LiveLayers are already showing this path. Host chrome only — never `CommonWatermarkPipeline` input, never Session `ImageInfo`, never `SourcePlaceholder`. May be soft / colour-shifted vs ImageIO. _Avoid_: placeholder, ProductThumb, “fast watermark”. |
| **Library Read upsell** | Ask **when the user picks photos**, with a dialog — never a chrome strip on Launch or Editor (About icon and Editor top bar stay clear). NotDetermined → system prompt on pick. Limited/Denied/Restricted → confirm (Settings / choose images anyway). “Anyway” skips the dialog for the rest of that Launch visit. Copy stays qualitative; no unmeasured “N% faster”. Must not block picking, editing, or export. _Avoid_: requiring Allow All to watermark. |
| **Watermarked preview** | Historical name for a baked `composeOverBackground` editor frame. **ADR-0033:** the editor slot is LiveLayers (photo + tiled cell), not this bitmap. Export / share / save-sheet thumbs still bake. `PreviewPurpose.Watermarked` remains a working-set type but is not the editor paint. _Avoid_: calling a Library derivative “the preview”. |
| **SourcePlaceholder** | Committed unwatermarked preview decode keyed by owned path + preview bucket in the cross-platform `PreviewImageRepository`. It is the live **photo layer** once a matching overlay exists; never paint it alone in the editor slot. A Library derivative must **not** be stored here. PhotoKit remains iOS-only. _Avoid_: “commit-bucket”. |
| **PreviewImageRepository** | Generic editor-preview working set (Source / Watermarked / leftover Filmstrip+Export slots). Decode stays at the platform edge (ADR-0030). Android/Desktop never write `SourceFastPath`. Filmstrip UI stays Coil (ADR-0028). |
| **ImageFormat** | App-owned export format enum in `shared/commonMain/data/model/ImageFormat.kt` (replaces `Bitmap.CompressFormat` in models/UI). JPEG honors quality (snapped to multiples of 20, min 20); PNG ignores it. |
| **Template** | Saved watermark text snippets (Room entity) in `shared/commonMain` with `TemplateRepository` + `TemplateEditor`; Android opens locale-selected prepopulated DB assets (`ewm-db-ch.db` / `ewm-db-eng.db`) in compatibility mode; Desktop and iOS copy matching locale seeds before Room opens with `BundledSQLiteDriver` only when the target DB does not yet exist (never reseed/overwrite existing user DBs). |
| **Recovery mode** | Crash-loop self-heal (ADR-0016): `MyApp`'s uncaught-exception handler increments the crash count, stores the stack trace, returns to Home, and exits. On a later launch when `MyApp.recoveryMode` is active, Android `MainActivity` renders the shared Compose `RecoveryScreen`; closing recovery calls `launchSuccess()` (clears the crash count/flag) and recreates the Activity. |

## Current state ownership

- Session owns the image list, current image, offsets, and export state. `WaterMarkRepository` only persists watermark configuration; it does not mirror Session images or feed selection back into Session. Selection and immediately following export use the same Session state.
- Output controls update only the edited field through `UserConfigRepository.updateFormat` or `updateCompressLevel`. Callers do not read and resubmit the other field; the former `OutputPrefsEditor` pair-write wrapper is removed. Android retains export-result invalidation on either edit.
- Editor preview publication uses `OverlayPreviewPolicy` (ADR-0033). The unused `PreviewPaintPolicy` and iOS baked-preview cache-hit stub are removed; tests must not require their names to remain in production source.

## Verification

After a product change: [`eval/README.md`](../eval/README.md) (select → scripts → heuristic → optional L3 → local report). Expected effect = the change’s description plus [`docs/testmap/copy.yaml`](testmap/copy.yaml) edge titles — not method names, and not an `expected:` field on `map.yaml`.

Pre-merge / pre-ship: skill `e2e-testmap` Mode B. Fill `docs/testmap/runs/<ts>-<sha>-verify.md` (gitignored) covering **stability** (script red/green + Agent Device N-repeat), **UI** (frames vs expected + human Confirm), and **performance** only when select suggested L3 (numbers do not own pass/fail). This is not a GitHub required check. Agents must not mint Confirm and must not recommend merge without that report.

The local testmap console keeps project data in `docs/testmap/` and the self-contained web client in `tests/testmap/web/`. The existing Python CLI owns execution and run records; the UI reads the catalog and runtime APIs. Run completion, script checks, independent review, and human confirmation are separate claims. Historical evidence stays attached to its run and package identity. The canonical operating skill is `skills/e2e-testmap/SKILL.md`, with linked discovery entries for agents. Continuous routes (ADR-0038) join only validated compatible device steps in one setup/session/restoration; route execution does not replace independent-case or Human Confirm evidence. The proposed Android model-directed journey (ADR-0039) adds one evidence-gated E2E runner beside the scripted cases and does not grant Human Confirm.

## User flows

pick image(s) (photo picker / share-in via ACTION_SEND) → edit in Editor (panels: content text/templates, style color+alpha+size, layout gap+rotation+tile mode, icon watermark) → save (format+quality) → share/open.

## Invariants (do not break silently)

- **Privacy:** fully offline; no tracking/crash SDKs; export strips ALL EXIF metadata including GPS (a feature, ADR-0009 — orientation is baked into pixels at decode instead). Android: no runtime permission on API ≥29 (pre-29 storage). iOS: pick needs no **Library Read**; save is add-only; **Library Read** is user-gated and optional.
- **Parity:** visual/behavioral changes vs production require an ADR or explicit product sign-off.
- **Preview gestures (ADR-0040, accepted 2026-10-18):** each gesture captures selection state before pointer down. Unselected gestures always pan/zoom the photo; selected gestures anywhere transform the single CLAMP cell or the whole REPEAT pattern. A completed tap on watermark pixels selects; a blank tap or Done clears selection; a subsequent tap on selected text opens the existing text sheet without a double-tap deadline. View/selection state never enters export.
- **Content editor theme** (ADR-0027): Editor chrome is a full photo-seeded dark `ColorScheme` when follow-photo is on (default), not the retired Palette-only background tint. Do not reintroduce `androidx.palette` / “thin bg only” as the product path.
- **Wallpaper dynamic color** (ADR-0027): Android-only; no OEM allowlist; do not claim wall/accent dynamic color on iOS/Desktop.
- **Cold Launch reveal** (ADR-0032): Android first Compose frame is opaque Launch. Do not `installSplashScreen`, keep, exit-listen, or hold Launch at alpha 0. OS splash (Android 12+) dismisses on first draw. iOS/Desktop keep the process-first 240 ms fade. iOS launch fill is `#262611` with no icon. Do not start the fade from `LaunchScreen` first composition. Do not retarget XML `md_theme_dark_background` to make the splash olive.
