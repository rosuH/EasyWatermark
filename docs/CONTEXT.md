# EasyWatermark Domain Context

Domain vocabulary and invariants. Agents and humans: use these words with these meanings; update this file when a concept is added, renamed, or retired (docs-with-code gate).

## Core concepts

| Term | Meaning |
|---|---|
| **Watermark cell** | The small offscreen bitmap containing one rendered instance of the watermark (text or icon, already rotated, with gap padding baked in). Built once, then tiled or placed. **ADR-0018:** product composition boundary is `CommonWatermarkPipeline` (decoded background + `WaterMark` + `TextRasterEnv` + optional icon + optional prepared `FontFamily` + fractional offsets → composed `ImageBitmap`). Android: `AndroidCommonRaster`. Desktop: `composeRealImage` + `DesktopRenderRequest` (C2). iOS: Preview `IosPreviewRaster` (720, in-memory) and Final Export `IosFinalRenderSpine` + `IosRenderRequest` (full-res, format/quality/offset; C3). Android native `WatermarkRenderer` remains measurement/golden oracle only. |
| **Tile mode** | How the cell covers the photo. `REPEAT` (UI: "repeat") = shader-tiled across the whole image. `CLAMP` (UI: "decal") = single instance at a draggable fractional offset. The model uses commonMain `WatermarkTileMode`; DataStore stores explicit `storageId` values that mirror the historical Android `Shader.TileMode.ordinal` values for byte-identical preferences. Android render/export converts only at the edge (`WatermarkTileMode.toShaderTileMode()` / `WaterMark.obtainTileMode()` in `TileModeExt.kt`). `MIRROR`/`DECAL` are representable but unreachable from UI. |
| **Gap (hGap/vGap)** | Spacing between tiles, percent-of-cell: `finalSize = cellSize * (gap/100 + 1)`. |
| **Rotation-AABB** | The axis-aligned bounding box of rotated content: `w' = w·cos+h·sin`, `h' = w·sin+h·cos`, with the degree piecewise-normalized (0–90 → d; 90–270 → |180−d|; else 360−d). Cell dimensions derive from it (text mode). Icon mode uses the icon **diagonal** for both dims instead. |
| **textSize dual duty** | For text: raw px size of the text paint (today view-px at preview scale — density-dependent). For icon: scale ratio = `textSize / 14f`. The CMP plan re-specs sizing to **image-space units** (fraction of image width) — requires a one-time config migration (ADR-0004, Proposed at C2b). |
| **Fractional offset (offsetX/offsetY)** | CLAMP-mode watermark position as 0..1 fractions of the displayed photo bounds. Survives across preview/export because it is resolution-independent. |
| **inSample preview decode** | Preview photos are decoded with `inSampleSize` (power of two, always ≥2) bounded by the view size; export decodes full-res. Skiko has no inSampleSize equivalent — iOS preview decode must be bounded another way (plan C5.2). |
| **ViewInfo (retired concept)** | Historical: a snapshot of the preview View's measured size/matrix once used to derive export scale (`1/MSCALE_X`, both axes — a known bug), with export blocked until the view reported it. **Removed in S3c-3** along with the `WaterMarkImageView` preview View — export scale is now image-space (S3a) and the Compose `Canvas` preview needs no view snapshot. Kept here only so the term is recognizable in older docs/commits; do not reintroduce it. |
| **Image-space sizing (target)** | Watermark dimensions defined relative to the source image, independent of any window/view size. Prerequisite for Desktop correctness. |
| **Golden two-tier** | (1) Strict same-platform goldens: old engine vs new engine, near-pixel-exact — the C2 gate. (2) Cross-platform perceptual diffs (SSIM-style, looser in text regions) with per-platform baseline sets — JVM/iOS Skia text ≠ Android Minikin text even with a bundled font. |
| **Parity baseline** | Production release **v2.10.0** (master). All UI migrations are measured against its screenshots/behavior, not against this branch's interim Compose screens. |
| **Shared CMP UI route** | The UI route of record is to migrate product screens from the existing Android Compose implementation into shared Compose Multiplatform UI. Android Compose is the source implementation for screen structure and interaction before final v2.10.0 parity; SwiftUI/Desktop-native UI is a temporary bring-up surface or a platform edge only. Keep native platform UI for app/window entry, system pickers, share/save/permission surfaces, platform capability glue, and renderer-specific paths that cannot be shared without breaking accepted Android native rendering decisions. |
| **composeResources (product UI)** | **ADR-0019 (accepted 2026-07-12).** Product strings + chrome icons/logo live in `shared/src/commonMain/composeResources/` (`values(-*)/strings.xml`, `drawable/`). Shared screens use `stringResource(Res.string.*)` / `painterResource(Res.drawable.*)` / `SharedProductDrawables` / `FuncType.label()` / `FuncType.iconPainter()`. Packaging on AGP 9 + Android-KMP library requires `androidResources { enable = true }` on `:shared` and must not rewrite `org.jetbrains.compose.components.*` to AndroidX. **Weblate** still points at `app/src/main/res/values-*` until retarget after merge to `master` (dual-write default EN until then). Not for watermark fonts or Room seed DBs. |
| **System-default watermark typeface** | Production Text-mode face resolution via Compose `FontFamily.Default` / platform resolver (ADR-0025). Not a bundled file. Bold/italic via platform synthesis. CJK coverage is an OS/language-pack property. |
| **Test-only bundled face** | Noto (or other) font files under test source sets (`desktopTest` / `androidTest`) for goldens and parity harnesses. Never a release payload (Play APK, iOS app, Desktop main resources). |
| **Supporting-pane editor** | Editor chrome pattern: **primary preview** + **secondary tools/inspector** (Material supporting-pane mapping for a media tool). Default dual-pane product shape on wide enough windows. **ADR-0026.** _Avoid_: calling the editor “list-detail”; list-detail is collection→item (e.g. optional gallery), not tool chrome. |
| **Three-zone batch editor** | **Withdrawn** for product chrome (ADR-0026 amended 2026-08-10). Was session library \| canvas \| inspector at ≥1440; left rail redundant with filmstrip. Do not reintroduce without ADR. |
| **Editor layout class** | Width-derived layout band for the shared editor (stack vs supporting-pane). Product breakpoints (ADR-0026): Compact **&lt;600**, Medium **600–839** (same vertical stack as Compact), dual-pane supporting-pane **≥840** (also for **≥1440** / `Wide` class). Filmstrip stays in the **primary preview pane** at every dual-pane band. |

## User flows

pick image(s) (photo picker / share-in via ACTION_SEND) → edit in Editor (panels: content text/templates, style color+alpha+size, layout gap+rotation+tile mode, icon watermark) → save (format+quality) → share/open.

## Invariants (do not break silently)

- **Privacy:** fully offline; no tracking/crash SDKs; no permissions on API ≥29; export strips ALL EXIF metadata including GPS (a feature, ADR-0009 — orientation is baked into pixels at decode instead).
- **Parity:** visual/behavioral changes vs production require an ADR or explicit product sign-off (Goal 2).
- Pinch-to-scale of the watermark is **disabled in production** (commented out) — keep it disabled for parity unless an ADR changes that.
- **Content editor theme** (ADR-0027): Editor chrome is a full photo-seeded dark `ColorScheme` when follow-photo is on (default), not the retired Palette-only background tint (S4d-41). Do not reintroduce `androidx.palette` / “thin bg only” as the product path.
- **Wallpaper dynamic color** (ADR-0027): Android-only; no OEM allowlist; do not claim wall/accent dynamic color on iOS/Desktop.
