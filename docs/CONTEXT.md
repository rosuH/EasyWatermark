# EasyWatermark Domain Context

Domain vocabulary and invariants. Agents and humans: use these words with these meanings; update this file when a concept is added, renamed, or retired (docs-with-code gate).

## Core concepts

| Term | Meaning |
|---|---|
| **Watermark cell** | The small offscreen bitmap containing one rendered instance of the watermark (text or icon, already rotated, with gap padding baked in). Built once, then tiled or placed. Today: `buildTextBitmapShader`/`buildIconBitmapShader`. Target: `WatermarkRenderer.buildCell()` in commonMain. |
| **Tile mode** | How the cell covers the photo. `REPEAT` (UI: "repeat") = shader-tiled across the whole image. `CLAMP` (UI: "decal") = single instance at a draggable fractional offset. The model uses commonMain `WatermarkTileMode`; DataStore stores explicit `storageId` values that mirror the historical Android `Shader.TileMode.ordinal` values for byte-identical preferences. Android render/export converts only at the edge (`WatermarkTileMode.toShaderTileMode()` / `WaterMark.obtainTileMode()` in `TileModeExt.kt`). `MIRROR`/`DECAL` are representable but unreachable from UI. |
| **Gap (hGap/vGap)** | Spacing between tiles, percent-of-cell: `finalSize = cellSize * (gap/100 + 1)`. |
| **Rotation-AABB** | The axis-aligned bounding box of rotated content: `w' = w·cos+h·sin`, `h' = w·sin+h·cos`, with the degree piecewise-normalized (0–90 → d; 90–270 → |180−d|; else 360−d). Cell dimensions derive from it (text mode). Icon mode uses the icon **diagonal** for both dims instead. |
| **textSize dual duty** | For text: raw px size of the text paint (today view-px at preview scale — density-dependent). For icon: scale ratio = `textSize / 14f`. The CMP plan re-specs sizing to **image-space units** (fraction of image width) — requires a one-time config migration (ADR-0004, Proposed at C2b). |
| **Fractional offset (offsetX/offsetY)** | CLAMP-mode watermark position as 0..1 fractions of the displayed photo bounds. Survives across preview/export because it is resolution-independent. |
| **inSample preview decode** | Preview photos are decoded with `inSampleSize` (power of two, always ≥2) bounded by the view size; export decodes full-res. Skiko has no inSampleSize equivalent — iOS preview decode must be bounded another way (plan C5.2). |
| **ViewInfo (retired concept)** | Historical: a snapshot of the preview View's measured size/matrix once used to derive export scale (`1/MSCALE_X`, both axes — a known bug), with export blocked until the view reported it. **Removed in S3c-3** along with the `WaterMarkImageView` preview View — export scale is now image-space (S3a) and the Compose `Canvas` preview needs no view snapshot. Kept here only so the term is recognizable in older docs/commits; do not reintroduce it. |
| **Image-space sizing (target)** | Watermark dimensions defined relative to the source image, independent of any window/view size. Prerequisite for Desktop correctness. |
| **Golden two-tier** | (1) Strict same-platform goldens: old engine vs new engine, near-pixel-exact — the C2 gate. (2) Cross-platform perceptual diffs (SSIM-style, looser in text regions) with per-platform baseline sets — JVM/iOS Skia text ≠ Android Minikin text even with a bundled font. |
| **Parity baseline** | Production release **v2.10.0** (master). All UI migrations are measured against its screenshots/behavior, not against this branch's interim Compose screens. |
| **WaterMark config model/rules** | Platform-neutral watermark configuration. **S4d-60 (accepted 2026-06-27)** moved `WaterMark`, `WatermarkMode`, `TextTypeface`, and `TextPaintStyle` into `shared/commonMain/data/model`; deleted the app-only `WaterMarkRepository.MarkMode` and `SerializableSealClass`; and kept Android render adapters at the edge (`WaterMark.obtainTileMode()` and `TextPaintStyle.obtainSysStyle()`). **S4d-61 (accepted 2026-06-27)** added commonMain `WatermarkConfigRules` for pure legacy normalization: text-size clamp, alpha percent→byte/byte clamp, h/v gap clamp, degree clamp, and text/icon mode transitions. Storage stayed byte-identical: `WatermarkMode.Text=0/Image=1`, `TextTypeface` keys 0-3, `TextPaintStyle` keys 0-1, `WatermarkTileMode.storageId`, DataStore keys, and Android render behavior unchanged. |
| **MediaRef** | Platform-neutral image identity (replaces `android.net.Uri` in models). **Landed (S4d-50, accepted)** as `@JvmInline value class MediaRef(val value: String)` in `shared/commonMain` (requires `import kotlin.jvm.JvmInline`). String-backed so DataStore round-trips with no migration: `KEY_ICON_URI` keeps storing `uri.toString()`; write `iconUri.value`, read `MediaRef.parse(it[KEY_ICON_URI] ?: "")`. Fields migrated: `WaterMark.iconUri` (S4d-50) and **`ImageInfo.uri` + `WaterMarkRepository.imageInfoMap` (S4d-52, accepted 2026-06-25)** — `imageInfoMap` now keys by `MediaRef` (value-class string equality preserves `imageInfoMap`/`isSameItem`/`select` semantics). Android `Uri` survives only at the edge via `utils/ktx/MediaRefExt.kt` (`MediaRef.toUri()` / `Uri.toMediaRef()`), mirroring the `ImageFormat`/`WatermarkTileMode` seam; S4d-52 converts `Uri↔MediaRef` at picker/share-in/gallery construction and decode/Coil/save edges, with strict goldens byte-identical (no rebaseline) and a 5-flow `emulator-5554` device gate. The dead `ImageInfo.shareUri` accessor was **removed (S4d-53)** — zero call sites; the real export result stays in `ImageInfo.result`/`jobState`. **Still `android.net.Uri` (deliberate Android edges):** gallery `Image.uri`, picker `Action.SystemPickerImageSelected.uriList`, `SaveExportSheet.imageUris`, picker contracts (`PickImageContract`/`MultiPickContract`), and `BitmapUtils`/`BitmapCache`/`FileUtils`/decode/Coil/save. The dead `KEY_URI`/`SP_KEY_URI` key declarations were **removed (S4d-54)** (`KEY_ICON_URI` + real prefs untouched) — **no model-layer `Uri` hygiene remains**. |
| **ImageInfo** | Transient selected/export image state. **S4d-71 (accepted 2026-06-27)** moved it from `:app` to `shared/commonMain/data/model` with the same package/FQN after `uri` had already become `MediaRef` and `shareUri` had been removed. `offsetX`/`offsetY` remain normalized 0f..1f fractional offsets by documented invariant; the old Android-only range annotation was dropped instead of adding AndroidX annotation to `:shared`. Room `Template` and UI `FuncTitleModel` remain app-side edge models (`UserPreferences` moved to commonMain in S4d-76). |
| **Watermark config command** | Platform-neutral editor config-change vocabulary. **S4d-72 (accepted 2026-06-27)** moved `FuncType` to `shared/commonMain/data/model` and added `WatermarkConfigChange`. `FuncTitleModel` remains app-side because it carries Android resource ids, but its `type` is now shared. `MainViewModel.onWaterMarkChanged` keeps the raw `Action.WaterMarkChange(item, any)` UI edge for now, maps it through `WatermarkConfigChange.from(FuncType, Any)` once, then dispatches typed commands to the existing update methods. |
| **DataStore store creation** | Platform-neutral *store-creation* seam (first DataStore KMP code in `:shared`). **S4d-74 (accepted 2026-06-27, commit `59eb6e0`)** added `shared/commonMain/.../data/datastore/CreateDataStore.kt` driver-free helper `createDataStore(storage: Storage<Preferences>) = DataStoreFactory.create(storage)` (no Android imports, **no `commonMain expect`**) and `shared/androidMain/.../CreateDataStore.android.kt` plain function (**not** `actual`) `createPreferencesDataStore(context, name)` = `PreferenceDataStoreFactory.create(produceFile = preferencesDataStoreFile(name), migrations = SharedPreferencesMigration(context, name))`. `:app` `di/DataStoreModule.kt` keeps the `Context.userDataStore`/`waterMarkDataStore` property names (so `RepositoryModule`/`AppModule` unchanged) with one store per file in-process. New catalog alias `datastore = androidx.datastore:datastore` (1.2.1); `:shared` `commonMain` uses both `datastore` + `datastore-preferences`. Stored path/format/migration byte-equivalent (no migration, no golden rebaseline). **Deferred:** no `commonMain expect`, no iOS/desktop store creation, Android does not route through the common storage helper (byte-identity needs `PreferenceDataStoreFactory.create(produceFile, migrations)`); `expect/actual` promotion needed a real common prefs consumer — landed in S4d-77 (see next row). |
| **UserPreferences / UserConfigRepository (commonMain)** | The first DataStore prefs model + consumer in `:shared`. **S4d-76 (commit `94aaf90`)** moved `UserPreferences` to `shared/commonMain/data/model` (same FQN), dropped Android `@Keep`, inlined `DEFAULT = UserPreferences(ImageFormat.JPEG, 80)` so the model no longer depends on `UserConfigRepository`. **S4d-77 (commit `e8e861e`)** moved `UserConfigRepository` to `shared/commonMain/data/repo` (same FQN) — the **first real common DataStore Preferences consumer**, resolving 3 edges with no dependency change: `okio.IOException` (not `java.io.IOException`; resolves via transitive `datastore-core-okio`, JVM typealias → identical Android behavior, compile-gated desktop+both iOS+app); `saveVersionCode(versionCode: Int)` keeping `BuildConfig.VERSION_CODE` at the Android caller edge (`MainViewModel.saveUpgradeInfo()`); and the inlined byte-identical changelog key `"sp_water_mark_config_key_change_log"` (so Android-side `WaterMarkRepository` is not a commonMain dep). `RepositoryModule`/`DataStoreModule` resolve the same FQN; Android store creation still via the S4d-74 helper. Persisted bytes unchanged (no migration, strict goldens 48/0). Future/gated: iOS/desktop store creation + `expect/actual createDataStore` promotion (now justified, not yet written); `WaterMarkRepository`/Room/templates stay Android-side. |
| **DynamicColorCapability** | Platform-neutral Material You gate (replaces direct `:cmonet`/`CMonet` in the live Compose consumers). **Landed (S4d-43, accepted 2026-06-25)** as `interface DynamicColorCapability { isAvailable(): Boolean; setForcedSupport(enabled: Boolean) }` in `shared/commonMain/.../platform`, bound as a Koin `single`. Android actual `AndroidDynamicColorCapability` delegates **verbatim** to unchanged `:cmonet` (same OEM allowlist + `dynamic_color_force` SP key); Desktop/iOS return `false` (static `Theme.kt` schemes are the fallback). Migrated consumers: `ComposeMainActivity` `AppTheme` gate + About-route initial toggle state, `AboutViewModel` toggle write — these must **not** call `CMonet` directly anymore. `:cmonet` is **retained** behind the actual; `MyApp.init`, `ContextExtension` getters, and the logo path still use `:cmonet` directly (owner-gated absorption follow-up). |
| **ImageFormat (planned)** | App-owned export format enum (replaces `Bitmap.CompressFormat` in models/UI). JPEG honors quality (snapped to multiples of 20, min 20); PNG ignores it. |
| **Template** | Saved watermark text snippets (Room entity), prepopulated from locale-selected bundled DBs (`ewm-db-ch.db` / `ewm-db-eng.db`). |
| **Recovery mode** | Crash-loop self-heal: uncaught-exception handler counts crashes, relaunches into a recovery screen (today: legacy `MainActivity` + `activity_recovery` layout) offering reset. Must survive `MainActivity` retirement (plan C1.6). |

## User flows

pick image(s) (photo picker / share-in via ACTION_SEND) → edit in Editor (panels: content text/templates, style color+alpha+size, layout gap+rotation+tile mode, icon watermark) → save (format+quality) → share/open.

## Invariants (do not break silently)

- **Privacy:** fully offline; no tracking/crash SDKs; no permissions on API ≥29; export strips ALL EXIF metadata including GPS (a feature, ADR-0009 — orientation is baked into pixels at decode instead).
- **Parity:** visual/behavioral changes vs production require an ADR or explicit product sign-off (Goal 2).
- Pinch-to-scale of the watermark is **disabled in production** (commented out) — keep it disabled for parity unless an ADR changes that.
- Preview background color comes from Palette extraction of the photo (cosmetic; kept for parity — kmpalette on CMP).
