管线已拆成 SourcePlaceholder（贵） 与 Watermarked（叠水印）。邻居 ±2 预热在代码里；回头切到已预热邻图，理论上应掉到 compose 量级。Phase 1 CG→Skia 是省内存，几乎不减这条 200 ms。

Preview 策略目前 关着 subsample。真机开 subsample @1920 大约 143→124 ms——有一点，打不穿「百毫秒地板」。FFmpeg / Skia HEIF / PhotoKit 读权限对这条路径不划算或不可用。

诚实上限：单张冷相册 HEIC、不降清晰度、不换解码器 → 大约就在 120–220 ms。要「瞬间」，只能缓存命中或事先预热。

② 拖参：已经便宜的，和还没验的

透明度 / 间距 / 字号等应走「清 Watermarked + 复用 Source」。偏移（CLAMP）额外有过队列问题。

项作用状态
Source 复用 改配置不重解底图 已落地
Icon 缓存 图片水印模式不每次重解 icon 已落地
Draft 背压 + 共享 Source 拖偏移：最多 1 飞 + 1 待；避免每采样一次 HEIC 代码有 · 真机未测
驱逐保 Source 内存紧时先丢 Watermarked，避免拖参退化成冷解 代码有 · hit 率未报

若 Source 被挤掉，拖参会瞬间退化成 ①——所以 ② 的流畅度也依赖工作集是否保住底图。

建议实验

先 ② 再 ①

E-live → E-switch

  • E-live：快速拖 CLAMP 偏移 + 常用透明度/间距滑条；看归因里 decode 是否接近 0，以及 draftRenders/draftSamples。
  • E-switch：连切 8 张相册 HEIC；首张允许 ~200 ms 类，已预热邻图应接近 compose；失败时确认仍是 decode 而不是 compose 回归。

胶片条 HTML / synthesis 仍在同目录，当作 HEIC 机制说明即可，不要当水印预览路线图。
