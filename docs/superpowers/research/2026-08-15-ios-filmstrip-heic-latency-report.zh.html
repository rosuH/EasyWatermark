胶片条 HEIC 为什么要近 200 ms，以及我们不该再调什么

四路并行调研（Apple ImageIO、Skia/Coil、FFmpeg/libheif、系统缩略图缓存）加上 iPhone 16 Pro 真机 S3 复测后的统一结论。

一句话

没有「128 px 税」可修——相机 HEIC 每次都在解整帧 HEVC tile 网格；要省时间，只能避免、复用或摊销这一次全解，而不是继续拧 ImageIO 旋钮。

真机已经关上的门

同进程、顺序平衡、8 张相册 HEIC。数字来自 s3-subsample-verify。

io128 · 胶片条尺寸
183→198 subsample +15 ms
factor 8 没有变便宜，反而略差
io1920 · 预览档
143→124 subsample −19 ms
1920 有小幅收益；128 别再赌 subsample

机制：钱花在 tile 上，不在「像素少」上

现代 iPhone 相册 HEIC 通常是约 63 块 512×512 的 HEVC tile 网格，不是「一张小图 + 一张大图」。

示意 · 7×9 HEVC tile grid

请求 128 或 1920，ImageIO 都要先解完全部 tile，再缩放。 现代文件里往往没有可单独解码的嵌入缩略图； IfAbsent 与 Always 成本等价。

所以 128 有时比 1920「更慢」，多半是固定开销的方差加上 128 侧采样更便宜—— 不是另有一个「小尺寸惩罚」 bug 等着被修好。

四路共识

细节在各研究文档；这里是对齐后的判断。

  1. 01
    ImageIO 选项字典已经到顶 Subsample / HDR→SDR / ShouldCache 等扫过；HEIF 上 subsample 只保证更小输出，不保证更快。生产路径已是天花板。
  2. 02
    Skia / Metal / 裸 CGImage 显示走不通 Skia 无 HEIF 解码器；skiko 不能把 MTLTexture 包成可读 BackendTexture；Compose 画非 Skia ImageBitmap 会抛。
  3. 03
    FFmpeg / libheif 不要上 FFmpeg 拼不出 tiled iPhone HEIC；libheif 是 LGPLv3，和 MIT + F-Droid 冲突。顺带：也没有可解的小 thmb 轨。
  4. 04
    PhotoKit 最快，却是错的隐私交易 要读相册授权；Limited 下 PHPicker 刚选的图也可能 fetch 为空。应用今天是 add-only——除非产品改姿态，否则拒绝。
  5. 05
    开 Coil 磁盘缓存帮不了 HEIC 它缓存的是源文件字节（贵的那份）。有用的是派生 JPEG sidecar，或系统 QL 缩略图缓存。

明确关掉

关掉再赌 SubsampleFactor 救 128
关掉VideoToolbox 降分辨率静图解码（设备返回 NotSupported）
关掉自研 libheif / FFmpeg / Rust 解码栈
关掉为胶片条引入 PhotoKit 读权限（除非单独 ADR）
别误会启用 Coil diskCachePolicy ≠ 派生缩略图缓存

值得做的事 · ROI 排序

都在「付一次全解，之后别再付」这个方向上。

  1. 从已驻留的预览帧派生 128

    焦点 ±2 的 preview 已经付过 ~180 ms；胶片条今天在对同一路径再解一次。命中时约 1 ms 绘制，未命中仍走原路径。

    隐私零成本 · 下一实验 · 无需新框架

  2. 应用自有 JPEG sidecar（写一次）

    首次解码后落一份 128/256 JPEG；之后重读主机侧 ~0.2–0.3 ms。会把用户像素缩小副本写进沙盒——需要你拍板。

    冷启动收益大 · owner 门控

  3. QLThumbnailGenerator

    无新权限、文件 URL 即可；系统持久缓存，热路径主机 ~1–2 ms。临时导入文件无扩展名，必须设 contentType。冷路径真机未知，禁止只凭 Mac 上的「快 3 倍」上线。

    须真机 A/B

  4. 带上 itemIdentifier

    picker 已能给；缓存键 / 去重 / 预选不依赖 PhotoKit 读权限。很小、独立。

    可随时落地

建议下一步

Experiment E1

胶片条命中预览工作集时，跳过第二次 HEIC 全解

不引入 Apple 新 API、不弹权限、不落盘用户照片副本。成功与否用真机毫秒数和截图目视即可判断，不必迷信主机上的 QL 比值。

  • 同一 owned path 若已有更大档位解码驻留 → 缩到 128 返回（Coil ImageFetchResult 一类）
  • 未命中 → 保持现有 ImageIO 路径
通过标准：已在预览工作集中的照片，胶片条 thumb 中位 < 5 ms（跳过解码）；截图与今日 128 格目视一致（ADR-0010）。

若 E1 之后冷导入 / 冷启动仍痛

再做 owner 门控 sidecar，然后才是真机 QL A/B。顺序不要颠倒。
