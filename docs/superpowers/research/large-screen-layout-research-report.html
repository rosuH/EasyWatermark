03 — Compose 官方最佳实践 developer.android.com

Window Size Classes（宽度）

  • Compact < 600dp — 绝大多数手机竖屏
  • Medium 600–840 — 平板竖屏、部分折叠内屏竖持
  • Expanded 840–1200 — 平板横屏、大折叠内屏横持
  • Large 1200–1600 · XLarge ≥1600 — 桌面/外接屏

用 currentWindowAdaptiveInfo()，按 app 窗口 而非 isTablet 分类。高度 Compact 时（手机横屏）勿硬双栏。

三大 Canonical Layout

  • List-detail — 列表 + 详情（邮件/笔记）
  • Supporting pane — 主内容 + 支持工具（媒体编辑）
  • Feed — 自适应网格（相册/社交）

官方明确：媒体编辑工具窗口属于 Supporting pane 用例。

关键 API（Android）

  • SupportingPaneScaffold / rememberSupportingPaneScaffoldNavigator
  • ListDetailPaneScaffold（胶卷→单图若做 gallery 双栏）
  • NavigationSuiteScaffold（底栏 ↔ 导航轨）
  • Nav3：ListDetailSceneStrategy / SupportingPaneSceneStrategy（adaptive skill 在 Nav3 路径上优先 SceneStrategy）
  • 折叠：WindowManager FoldingFeature（HALF_OPENED + orientation）
@AndroidDev（X）： 用 Material 3 Adaptive，勿锁方向；可调整窗口与多窗口；适配折叠/展开。

对齐官方 Supporting pane 与 Photos/iPad 编辑。 对现有 I1 Expanded 改动最小。

Snapseed/Markup 取向：瓦片检视优先； Medium+ 用竖向 FuncType rail + 临时 sheet。

推荐 Compact多一步点开

Scheme C · Batch power

Three-Zone Batch Studio

┌ Lib │ Canvas │ Insp. ┐ │ img │ big │ tabs │ │ tpl │ │ │ └─────────────────────┘

Lightroom Classic / Canva 桌面：库+画布+检视器。 批处理/模板最强，手机需折叠为 A/B。

桌面 ≥1440重工程

交互形态对照

  • A — 参数常驻可见（透明度/间距/旋转边调边看瓦片）；胶卷在侧栏顶部。
  • B — 渐进披露：默认只看画布；点 rail 弹出 Content/Style/Layout 面板；可双击隐藏 chrome。
  • C — 左栏选图/模板即换中心预览；右栏为当前选中图的 inspector；适合多图批次导出。

07 — 推荐代码路径

短期（打磨 A，对齐 WSC）

  • 断点：Expanded 降至 840dp（或保留 1024 但 Medium 半双栏）
  • 右栏：固定宽 + 水平 padding；去掉贴边裁切
  • 预览：取消双重 12dp；大窗 Fit 更贴边
  • Gallery：继续 GridCells.Adaptive

中期（官方组件）

  • Android：评估 SupportingPaneScaffold
  • 已在 Nav3 上：考虑 SupportingPaneSceneStrategy
  • CMP commonMain：继续手写 Row 策略（与官方 70/30 对齐）
  • 折叠：Android 侧注入 FoldingFeature → layout flags

08 — 建议决策
  1. 产品默认 IA = A（Supporting Pane Studio），与官方媒体编辑用例一致。
  2. Phone Compact 采用 B 的交互密度（预览优先、控件可收起），视觉可仍是竖栈。
  3. Desktop 先修 A 全屏缺陷（已报空边/裁切），再评估 C 是否值得做批处理三区。
  4. 断点与官方对齐：至少 Medium 行为有别于 Compact；Expanded 不晚于 840–900dp。
  5. 折叠与鼠标/键盘作为增强，不阻塞 A 修复。
相对当前 I1： 不是推倒重来，而是「A 打磨 + Compact 注入 B 的沉浸感 + 桌面可选 C」。
