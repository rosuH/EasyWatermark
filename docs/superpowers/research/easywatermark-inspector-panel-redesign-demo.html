EasyWatermark · Supporting-pane inspector redesign

右侧属性面板重新设计 DEMO

现状把手机底栏 carousel竖着塞进侧栏：控件垂直居中、中间大片死区、 文字框与 Text/Icon 切换失序。本 DEMO 对标 Lightroom Develop / Canva Properties / Figma 右侧属性栏， 给出表单式、顶对齐、可滚动的 inspector 编排（仅设计；未改产品代码）。

问题 phone chrome → tall side pane 参照 LR / Canva / Figma / Photos tablet 目标 320–360dp form inspector 不变 Content · Style · Layout 信息架构

问题诊断（对照你截的右侧）

根因不只是「丑」，而是布局合同错了：侧栏用了 fillMaxSize + Center 的手机控件框。

P1 · 垂直居中

控件漂在中间

EditorOptionControlFrame 用 Alignment.Center，侧栏变高后上下空、中间挤一团。

P2 · 死区

Tab 贴底、内容贴中

内容区与底 Tab 之间大块空白无信息、无滚动锚点，像「坏了的手机底栏」。

P3 · 层级

字段无标签行

「请勿转载」像裸输入框；Text/Icon 大卡片与底 Tab 重复表达「内容」语义。

P4 · 节奏

手机 carousel 不适配侧栏

生产是「选 option → 中间出控件」；侧栏应改为「分区表单一次扫完」。

成熟产品怎么排右侧

共性：属性区顶对齐、可滚动、分区标题 + 标签/值同行；画布优先，面板固定宽。

产品 右侧 / 工具区模式 可借鉴
Lightroom Classic Develop 右栏：Basic / Tone 等可折叠分区，滑块 label 左、数值右 分区标题 + 紧凑滑块行；永不垂直居中
Canva 选中后 properties / edit panel：顶到底表单；左栏是内容库 「库在左、属性在右」；表单密度
Figma 右栏 Design：Fill / Stroke / Effects 堆叠；section header 极窄 12px 字号标签、8–12 间距节奏
Google Photos（平板） 编辑工具进侧栏，非手机底栏原样放大 同功能、换 chrome；侧栏是另一套编排
Snapseed 单工具模态底栏（手机） 不适合 EW 多参数实时平铺；仅作手机参考

现在 vs 提案（同宽 inspector）

左侧模拟当前；右侧为提案。点提案顶上的 Content / Style / Layout 切换。

编排原则（落地时写进实现）

01

侧栏 ≠ 竖着的底栏

Phone 保留 bottom sheet/carousel；Expanded/Wide 换 Form Inspector 组件，不复用 Center 框。

02

顶对齐 + 可滚动

内容从顶开始；控件多时 scroll，禁止为了「好看」垂直居中。

03

标签 / 值同行

滑块：左 label、右 mono 数值；输入框上方固定 field label。

04

Segment 替代大卡片

Text/Icon 用等宽 segment；模式切换后下方字段替换，不并排占两格大气泡。

05

Tab 吸顶，不吸底

Content/Style/Layout 放 inspector 顶部（或 sticky header），底部留给安全区/次要动作。

06

IA 可不变

仍三 Tab + 现有 FuncType 能力；改的是信息架构的呈现节奏，不是砍功能。
